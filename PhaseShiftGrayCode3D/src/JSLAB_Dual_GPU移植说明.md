## 版本差异详情

### v1.1(当前)

#### 1. 处理流程
与 CPU V2 **完全一致**,无步骤增删:

- 解码:`3×3 预模糊 → 各频率包裹相位(atan2) → 调制 → 外差解包(round) → 级次图`
- 重建:`立体匹配(级次约束) → 视差 5×5 中值(可选) → 重投影 3D(Q+R1+深度截断) → 点云高斯滤波 → 半径离群滤波(ROR)`

#### 2. 结构差异(结果等价,实现不同)

**解码器 —— 预模糊融合**
预模糊融进解码核(`blurredSample` 实时计算 3×3),不再单独生成、存储整叠模糊帧,
显著降低显存占用。

**重建器 —— 立体匹配候选查找**
- CPU:每行构建 `std::vector` 的 `row_rank_table`(级次 k → 右图列号列表)。
- GPU:`buildOrderRangeKernel` 用 `atomicMin/atomicMax` 预计算「每行、每个级次 k
  出现的列区间 `[col_min, col_max]`」,匹配时只扫描该区间(仍复核 `r_k == k`)。
- **候选集合完全相同**,视差图与 CPU **逐位一致(MaxDiff = 0)**;
  既避免了 device 上无法使用的 `std::vector`,又消除了「每像素扫描整行」的
  `O(cols)` 开销(这是 v1.0 比 CPU 慢的最大原因)。

#### 3. 精度分层(数值差异的唯一来源)

| 阶段 | CPU | GPU | 实测差异 |
|---|---|---|---|
| 解码相位(atan2/sqrt/解包 round) | double | **double** | 仅 CUDA 与 MSVC `atan2/sqrt` 末位 ULP 差异 → 级次图约 5/26M 个边界像素不同(<1e-4%);相位图差 ~1e-13 |
| 立体匹配(相位残差 + 抛物线亚像素) | double | **double** | **0(逐位一致)** |
| 重投影 3D(Q/R1 运算) | double | **double 运算,xyz 存 float**(CV_32FC3) | 坐标微米级量化 |
| 点云高斯滤波 / ROR(距离/计数/阈值比较) | double | **float** | 约 1e-2% 临界点的「保留/剔除」判定与 CPU 不同 |

> 若需点云有效点数与 CPU **完全一致**:把高斯/ROR 的坐标差与 `count/dist2/阈值`
> 比较改为 double 即可(代价是显存带宽与少量速度,精度上通常无必要)。

#### 4. 内存与 I/O

- **解码原图按 8-bit(CV_8U)上传**:对 8-bit 采集无损,PCIe 与显存比 float 少 4×;
  非 `CV_8U` 输入会先 `convertTo(CV_8U)`。
- 解码 **设备缓冲持久化**(`JSLAB_DecodePhase_GPU` 内 static 缓冲,左右两次解码复用),
  不再每次 `cudaMalloc/cudaFree` 数 GB。
- 重建全程 **device-to-device**:单次上传(相位/级次)、单次下载(xyz/P),无逐阶段回主机。
- **CUDA 预热**:`JSLAB_DecodePhase_GPU_Warmup()`(内部 `cudaFree(0)`)可在计时/首次
  使用前调用,把一次性的上下文初始化开销移出解码计时。

#### 5. 性能基准

测试:5120×5120,3 频(107/100/94),每频 8 步共 24 帧;Release x64。
(`JSLAB_Demo_Dual.cpp` 的 `rebuild_v2` / `rebuild_v2_gpu` 分段计时)

| 阶段 | CPU | GPU | 加速 |
|---|---|---|---|
| decode | ~2.6–3.9 s | ~1.1 s | 约 3–4× |
| setData/remap | ~0.4 s | ~0.13 s | 约 3× |
| reconstruct | ~4.8 s | ~0.31 s | **约 15×** |
| **总计** | ~7.8–9.2 s | **~1.5 s** | **约 6×** |

#### 6. 已知差异 / 注意事项
- 级次图边界 ~5 像素、点云 ~0.01% 边界点的差异属既定精度策略,可忽略。
- decode 仍是 GPU 端主要耗时;其下限来自 double 的 `atan2/sqrt`/解包(消费级显卡
  FP64 吞吐低)。如需进一步提速只能做混合精度,但有级次图翻周期风险,默认不采用。

### v1.0

首个 GPU 移植版本,目标是**逐位对齐 CPU**,未做性能优化。

- 流程与 CPU 一致;解码/匹配关键路径已用 double 保证 `round`/亚像素与 CPU 一致。
- **立体匹配为「整行扫描」**(每个左像素遍历整行右像素找同级次匹配),
  以严格复现 CPU 的 `row_rank_table` 语义;该实现 `O(cols)`/像素,是本版本
  **GPU 反而比 CPU 慢**的主因。
- 解码按 double 上传整叠帧并单独做预模糊,显存/带宽开销大;每次调用都重新分配设备内存。
- 关键修复(对齐 CPU):视差缓冲 `cudaMemset` 清零;立体匹配恢复 double;
  高斯滤波输出掩码与 ROR 同步;解码全程 double 修正高频解包的整周期跳变;
  修复解码器输出的浅拷贝混叠。

> v1.1 在保持上述正确性的前提下,针对结构/精度/内存做了等价优化,见上节。

## 附录

### 性能基准(测试条件)
- 图像:5120×5120 灰度,8-bit
- 频率:107 / 100 / 94,各 8 步相移,合计 24 帧/侧
- 配置:Release | x64,OpenCV GPU 版,CUDA 12.8
- 计时口径:解码(左+右)/ setData+remap / 重建(匹配→ROR),不含读图与存盘

### 术语
- **级次图(order map / k)**:外差解包得到的条纹周期序号,用于立体匹配的级次约束。
- **视差(disparity)**:左右极线校正后同名点的列差。
- **重投影(reproject)**:用 Q 矩阵把(列, 行, 视差)透视除法成 3D,再经 R1 旋转回相机系。
- **ROR(Radius Outlier Removal)**:半径邻域内有效邻点数不足则剔除。
